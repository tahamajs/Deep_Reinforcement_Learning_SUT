\begin{abstract}
This document provides a comprehensive, reproducible description of the CA23
scaffold: design goals, implementation details, algorithmic building blocks,
experimental protocols, and best practices for reproducible reinforcement
learning experiments. The report is intended as a short, self-contained piece
suitable for inclusion in a course submission or as the basis for a short
conference-style write-up. We include equations for the optimization
objectives, suggested hyperparameter sweeps, metrics and statistical tests,
and instructions for packaging and sharing results.

\section{Introduction}
Reinforcement learning (RL) experiments often require careful attention to
reproducibility: controlled randomness, configuration management, and clear
reporting of evaluation metrics. The CA23 scaffold provides a minimal,
well-documented toolkit for implementing policy-gradient style agents and
evaluating them on canonical control tasks. Our goals are (1) to make it easy
for students and researchers to implement and iterate on policy-gradient
algorithms, and (2) to ensure experiments are reproducible and reportable.

This report expands on the short `REPORT.md`: it formalizes the loss
functions, provides pseudocode, and specifies a complete experimental protocol
for a small set of baseline experiments (baseline, entropy sweep, network
capacity ablation, learning rate sensitivity).

\section{Quickstart and Environment Setup}
A reproducible RL research workflow begins with a clean, isolated Python environment. We recommend using Python virtual environments (\texttt{venv}) to avoid dependency conflicts and ensure that all required packages are installed locally. The steps are:
\begin{enumerate}
  \item \textbf{Create a virtual environment:} \texttt{python -m venv .venv} creates a new environment in the project directory.
  \item \textbf{Activate the environment:} On Unix/macOS, use \texttt{source .venv/bin/activate}. On Windows, use \texttt{.venv\\Scripts\\activate}.
  \item \textbf{Upgrade pip and install dependencies:} Always upgrade pip to the latest version, then install all required packages from \texttt{requirements.txt} to ensure consistent versions.
  \item \textbf{Editable install:} For development, install the package in editable mode (\texttt{pip install -e .}) so that code changes are immediately reflected.
  \item \textbf{Testing:} Use \texttt{pytest} to run all unit and integration tests. The CA23 scaffold uses \texttt{pytest.importorskip} to allow tests to run even if optional dependencies are missing, making the suite robust to partial environments.
\end{enumerate}
This approach ensures that experiments are portable and can be reproduced on any compatible system.

\section{Background}
Reinforcement learning (RL) is a framework for sequential decision making where an agent interacts with an environment to maximize cumulative reward. The agent observes a state $s_t$, selects an action $a_t$, receives a reward $r_t$, and transitions to a new state $s_{t+1}$. The environment is typically modeled as a Markov Decision Process (MDP) defined by $(\mathcal{S}, \mathcal{A}, P, r, \gamma)$, where $\mathcal{S}$ is the state space, $\mathcal{A}$ is the action space, $P$ is the transition probability, $r$ is the reward function, and $\gamma$ is the discount factor. RL algorithms can be broadly categorized into value-based, policy-based, and actor-critic methods. Policy-gradient methods directly optimize the policy by estimating gradients of expected return with respect to policy parameters.

\section{Related work}
Classic references include Sutton and Barto's textbook \cite{sutton_barto},
which derives policy-gradient estimators and advantage-based variance
reduction techniques. OpenAI Spinning Up provides practical implementation
advice and recipes for common algorithms (policy gradient, PPO) \cite{spinup}.
This scaffold intentionally targets the policy-gradient family and provides a
clear place to insert improvements such as GAE, baselines, or trust-region
updates.

\paragraph{Policy Gradient Methods} The REINFORCE algorithm \cite{williams1992simple} is the foundational Monte Carlo policy-gradient method. Actor-critic methods \cite{konda2000actor} combine policy-gradient updates with value function baselines to reduce variance. Trust Region Policy Optimization (TRPO) \cite{schulman2015trust} and Proximal Policy Optimization (PPO) \cite{schulman2017proximal} are modern, robust policy-gradient algorithms.

\paragraph{Reproducibility in RL} Henderson et al. \cite{henderson2018deep} highlight the challenges of reproducibility in deep RL, including sensitivity to random seeds, hyperparameters, and environment stochasticity. Our scaffold addresses these by enforcing strict configuration management and logging.

\section{Environments}
The primary environment used in CA23 is \texttt{CartPole-v1}, a classic control benchmark from OpenAI Gym. The state space is continuous (cart position, velocity, pole angle, angular velocity), and the action space is discrete (left/right). The episode terminates when the pole falls or after 500 steps. The environment is fully observable and deterministic except for initial state randomization. The scaffold can be easily extended to other Gym environments (e.g., MountainCar, Acrobot, LunarLander) by changing the `env_name` in the config.

\paragraph{MountainCar-v0} A continuous state, discrete action environment where the agent must build momentum to reach the goal. Episodes are challenging due to sparse rewards.

\paragraph{LunarLander-v2} A more complex environment with continuous state and discrete actions, requiring precise control to land a spacecraft.

\paragraph{Continuous Control (Pendulum-v0, BipedalWalker-v3)} The scaffold can be extended to continuous action spaces by using Gaussian policies and adapting the loss functions accordingly.

\section{Methods}
\subsection{Policy and value parameterization}
We use simple multi-layer perceptrons for both policy and value networks. For a
categorical action space, the policy $\pi_\theta(a|s)$ is parameterized by a
network returning action logits; action probabilities are given by softmax.
The value network $V_\phi(s)$ returns a scalar estimate of expected return.

\subsection{Objectives}
Let $\tau = (s_0,a_0,r_0,\dots,s_T)$ be an episode. The return from time $t$ is
$$R_t = \sum_{k=t}^{T} \gamma^{k-t} r_k$$
The policy gradient objective can be written as
$$J(\theta) = \mathbb{E}_\tau\left[ \sum_{t=0}^{T} \log \pi_\theta(a_t|s_t) A_t \right],$$
where $A_t$ is an estimator of advantage (we use $A_t = R_t - V_\phi(s_t)$ as
a simple baseline). Minimizing the negative expected advantage gives the
loss used in code:
$$\mathcal{L}_\text{policy} = -\mathbb{E}_t[\log \pi_\theta(a_t|s_t) A_t].$$

We also include a value-function loss (MSE):
$$\mathcal{L}_\text{value} = \mathbb{E}_t\left[(V_\phi(s_t) - R_t)^2\right].$$
Entropy regularization encourages exploration by adding a term to encourage
high-entropy policies. Denoting the entropy of the policy at state $s$ by
$\mathcal{H}(\pi(\cdot|s))$, the combined loss minimized is
$$\mathcal{L} = \mathcal{L}_\text{policy} + c_v \mathcal{L}_\text{value} - \lambda \mathbb{E}_t[\mathcal{H}(\pi(\cdot|s_t))],$$
where $c_v$ is the value loss coefficient and $\lambda" is the entropy
regularization coefficient (in our code `entropy_coef`).

\subsection{Numerical and implementation details}
- Policy action selection uses PyTorch's `Categorical` distribution to obtain
  actions and log-probabilities. For deterministic evaluation we pick the
  argmax of the probabilities.
- Careful dtype handling is used in `src/losses.py` so tests remain stable with
  mixed dtypes.
- To support multiple gym versions, we handle both the older `(obs, reward,
  done, info)` and newer `(obs, reward, terminated, truncated, info)` step
  signatures.

\section{Mathematical Derivations}
\subsection{Policy Gradient Theorem}
The policy gradient theorem states that for a differentiable policy $\pi_\theta(a|s)$, the gradient of the expected return $J(\theta)$ with respect to parameters $\theta$ is:
$$
\nabla_\theta J(\theta) = \mathbb{E}_{\pi_\theta}\left[ \nabla_\theta \log \pi_\theta(a|s) Q^{\pi_\theta}(s,a) \right]
$$
where $Q^{\pi_\theta}(s,a)$ is the action-value function. In practice, we use an advantage estimator $A_t$ to reduce variance.

\subsection{Variance Reduction and Baselines}
Subtracting a baseline $b(s)$ from the return does not introduce bias but can reduce variance:
$$
\nabla_\theta J(\theta) = \mathbb{E}_{\pi_\theta}\left[ \nabla_\theta \log \pi_\theta(a|s) (Q^{\pi_\theta}(s,a) - b(s)) \right]
$$
A common choice is $b(s) = V_\phi(s)$, the learned value function.

\subsection{Entropy Gradient}
The entropy of a categorical policy is $\mathcal{H}(\pi(\cdot|s)) = -\sum_a \pi(a|s) \log \pi(a|s)$. The gradient with respect to $\theta$ is:
$$
\nabla_\theta \mathcal{H}(\pi_\theta(\cdot|s)) = -\sum_a \nabla_\theta \pi_\theta(a|s) (1 + \log \pi_\theta(a|s))
$$
Adding this term to the loss encourages exploration.

\section{Worked Example: Policy Gradient Calculation}
Suppose the agent observes a state $s$ and takes action $a$ with probability $\pi_\theta(a|s) = 0.7$, receiving reward $r=1$. The log-probability is $\log 0.7 \approx -0.357$. If the advantage $A = 2.0$, the policy gradient loss for this step is $-\log 0.7 \times 2.0 = 0.714$. For a batch, average over all steps. This illustrates how the loss encourages actions with positive advantage and discourages those with negative advantage.

\section{Implementation Pitfalls and Debugging}
\begin{itemize}
  \item \textbf{Reward scaling:} Large or unnormalized rewards can destabilize training. Normalize rewards if necessary.
  \item \textbf{Gradient explosion:} Use gradient clipping to prevent large updates.
  \item \textbf{Incorrect advantage computation:} Always check that advantages are computed with the correct bootstrapping and discounting.
  \item \textbf{Seed leakage:} Ensure all sources of randomness (numpy, torch, env) are seeded.
  \item \textbf{Silent bugs:} Use assertions and unit tests for tensor shapes and value ranges.
\end{itemize}

\section{Visualization and Interpretability}
Visualizing learning curves, policy entropy, and value estimates is crucial for diagnosing training. Use moving averages and error bands to summarize results. For interpretability, visualize policy outputs (action probabilities) and value function landscapes. For environments with spatial structure, plot state visitation heatmaps.

\section{Advanced Visualization Techniques}
\subsection{t-SNE and Embedding Analysis}
Use t-SNE or PCA to visualize high-dimensional state or policy embeddings, revealing structure in learned representations.

\subsection{Saliency Maps}
For environments with image observations, compute gradients of the value or policy output with respect to input pixels to identify salient regions.

\subsection{Policy and Value Landscapes}
Plot the output of the policy or value function over a grid of states to interpret agent behavior and detect overfitting or blind spots.

\section{Repository Layout and Modular Design}
The CA23 repository is organized to separate concerns and promote clarity:
\begin{itemize}
  \item \textbf{src/} contains all core modules, each with a single responsibility:
    \begin{itemize}
      \item \texttt{config.py}: Defines the \texttt{ExperimentConfig} dataclass for all hyperparameters and YAML serialization.
      \item \texttt{model.py}: Implements \texttt{PolicyNetwork} and \texttt{ValueNetwork} using PyTorch, with configurable architectures.
      \item \texttt{losses.py}: Contains loss functions for policy gradient, value fitting, and entropy regularization.
      \item \texttt{data.py}: Provides episode collection and discounted return computation utilities.
      \item \texttt{utils.py}: Offers seeding, device selection, and figure saving helpers.
    \end{itemize}
  \item \textbf{configs/} holds example YAML configuration files for quick experimentation and reproducibility.
  \item \textbf{scripts/} includes entry-point scripts (e.g., \texttt{train.py}) for running experiments.
  \item \textbf{tests/} contains all unit and integration tests, ensuring correctness and import-safety.
\end{itemize}
This modular design makes it easy to extend, test, and maintain the codebase.

\section{Experimental design}
We provide a canonical experimental protocol intended to be reproducible and
interpretable. Experiments recommended for a short course project include:

\begin{enumerate}[itemsep=2pt]
\item Baseline: run the default config on \texttt{CartPole-v1} for 5 seeds.
\item Entropy sweep: \(\lambda \in \{0.0, 0.01, 0.1\}\) across 5 seeds.
\item Network capacity ablation: hidden sizes in \{(32,32), (64,64), (128,128)\}.
\item LR sensitivity: learning rates \{1e-4, 1e-3, 3e-3\}.
\end{enumerate}

For each experiment report the per-episode return, policy and value losses,
entropy, and the wall-clock time per episode. Use a consistent stopping
criterion or fixed number of episodes across runs for fair comparison.

\section{Evaluation metrics and statistical tests}
Primary metric: mean episode return computed per episode and smoothed with a
moving average (window 50). For comparing conditions, compute the mean and
standard deviation of final returns across seeds and report confidence
intervals. For pairwise comparisons use a two-sided t-test and report p-value
and Cohen's d for effect size.

\section{Reproducibility checklist}
Follow this checklist to ensure reproducible runs and publishable artifacts:
\begin{itemize}
\item Save `config.yaml` for each run under `runs/<id>/config.yaml` using
  `ExperimentConfig.to_yaml`.
\item Record git commit hash (e.g., `git rev-parse HEAD`) and include it in the
  run metadata.
\item Store `pip freeze` in the run folder or an environment YAML.
\item Record seeds and, when using GPUs, device identifiers.
\item Save per-episode logs and model checkpoints.
\item Report aggregated results with mean ± std across seeds and include the
  raw data (CSV) in a `results/` folder for easy re-analysis.
\end{itemize}

\section{Reproducibility and Reporting: Principles and Rationale}
Reproducibility is a cornerstone of scientific research. In RL, it is especially important due to the stochastic nature of environments and learning algorithms. CA23 enforces reproducibility by:
\begin{itemize}
  \item \textbf{Seeding all random number generators:} Use \texttt{src.utils.set_seed} to set seeds for Python, NumPy, PyTorch, and (if applicable) the environment.
  \item \textbf{Config versioning:} Save the exact YAML config used for each run, and record the git commit hash and environment details.
  \item \textbf{Automated figure saving:} Use \texttt{src.utils.save_figure} with high DPI to ensure publication-quality plots.
  \item \textbf{Comprehensive logging:} Log all metrics, hyperparameters, and environment details for each run.
\end{itemize}
Reporting should include not only results but also the full experimental context, enabling others to reproduce and extend the work.

\section{Running Experiments: Concepts and Best Practices}
Experiments are run using the provided \texttt{scripts/train.py}, which loads a YAML config and executes a training loop. Key concepts:
\begin{itemize}
  \item \textbf{Configuration-driven:} All experiment parameters are specified in a YAML file, ensuring that runs are fully documented and reproducible.
  \item \textbf{Logging:} Results (returns, losses) are logged to CSV files in a \texttt{runs/} directory, and plots are saved to \texttt{pictures/} for later analysis.
  \item \textbf{Separation of code and config:} By keeping code generic and using configs for specifics, the same codebase can be used for many experiments.
  \item \textbf{Batch runs:} For sweeps, generate multiple configs and run \texttt{train.py} for each, organizing outputs by experiment and seed.
\end{itemize}
This approach supports both single-run debugging and large-scale hyperparameter sweeps.

\section{Troubleshooting Common Errors}
\begin{itemize}
  \item \textbf{ImportError: No module named 'src'}: Ensure you run scripts from the project root or set PYTHONPATH.
  \item \textbf{CUDA out of memory}: Reduce batch size or use CPU.
  \item \textbf{NaN losses}: Check for exploding gradients, invalid operations (e.g., log(0)), or unnormalized inputs.
  \item \textbf{Test failures}: Run \texttt{pytest -v} and check stack traces; ensure all dependencies are installed.
\end{itemize}

\section{Contributing: Guidelines and Rationale}
Contributions to CA23 should follow best practices for open-source and scientific software:
\begin{itemize}
  \item \textbf{Import-safety:} All modules must be import-safe (no side effects on import) to ensure that tests and scripts can import code without triggering computation.
  \item \textbf{Testing:} Every new feature or bugfix should be accompanied by a test. Prefer small, focused tests that are easy to debug.
  \item \textbf{Documentation:} All algorithmic choices and design decisions should be documented in \texttt{REPORT.md} or inline comments.
  \item \textbf{Code review:} Use pull requests and code review to maintain code quality and share knowledge.
\end{itemize}
This ensures that the codebase remains robust, maintainable, and useful for the community.
