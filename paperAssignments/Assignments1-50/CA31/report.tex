\section{Introduction}
Reinforcement Learning (RL) is a subfield of machine learning concerned with how agents can learn optimal behaviors through interaction with their environment. Unlike supervised learning, where labeled examples guide the learning process, RL agents must discover effective strategies via trial-and-error, receiving only sparse reward signals. This paradigm is particularly powerful for problems involving sequential decision-making, such as autonomous driving, game playing (e.g., AlphaGo), robotics, and resource allocation in networks.

Actor-Critic methods represent a hybrid approach in RL, merging the strengths of policy-based methods (which directly optimize the policy) and value-based methods (which learn to estimate the value of states or actions). The "actor" component learns a stochastic or deterministic policy to select actions, while the "critic" provides a value function that serves as a baseline to reduce variance in policy updates. This combination often leads to more stable and sample-efficient learning compared to pure policy gradients or pure value iteration.

Advantage Actor-Critic (A2C) is a specific instantiation of actor-critic algorithms, introduced as a synchronous alternative to Asynchronous Advantage Actor-Critic (A3C). A2C addresses the instability issues in A3C by collecting rollouts from multiple parallel environments in a deterministic manner, ensuring consistent gradient estimates across updates. This makes A2C easier to implement and debug while maintaining the benefits of parallel data collection for variance reduction.

This report details a complete, from-scratch implementation of A2C using PyTorch, including a small but fully reproducible Bernoulli bandit example for quick validation. We cover the theoretical foundations, algorithmic details, implementation specifics, experimental setups, illustrative results, and reproducibility guidelines. The code is designed to be modular, type-hinted, and import-safe, making it suitable for educational purposes, research prototyping, and extension to more advanced RL techniques. We also include a discussion of related work, limitations, and potential future directions, providing a comprehensive guide to actor-critic methods in RL.
\section{Background and Notation}
In this section, we establish the foundational concepts and notation used throughout the report. We assume familiarity with basic probability and linear algebra, but provide brief explanations where necessary.

\subsection{Markov Decision Processes (MDPs)}
Reinforcement learning is typically formulated within the framework of Markov Decision Processes (MDPs). An MDP is defined by a tuple $(\mathcal{S}, \mathcal{A}, \mathcal{P}, \mathcal{R}, \gamma)$, where:
- $\mathcal{S}$ is the set of states, representing the environment's configuration.
- $\mathcal{A}$ is the set of actions available to the agent.
- $\mathcal{P}(s'|s,a)$ is the transition probability distribution, specifying the likelihood of moving to state $s'$ from state $s$ after taking action $a$.
- $\mathcal{R}(s,a,s')$ is the reward function, providing immediate feedback for transitions.
- $\gamma \in [0,1)$ is the discount factor, weighting future rewards relative to immediate ones.

The agent's goal is to find a policy $\pi: \mathcal{S} \to \mathcal{P}(\mathcal{A})$ that maximizes the expected cumulative discounted reward, known as the return.

\subsection{Key Definitions}
We denote the state at time step $t$ as $s_t \in \mathcal{S}$, the action taken as $a_t \in \mathcal{A}$, and the reward received as $r_t = \mathcal{R}(s_t, a_t, s_{t+1})$. The return $G_t$ from time $t$ onward is defined as:
\begin{equation}
G_t = \sum_{k=0}^{\infty} \gamma^k r_{t+k}.
\end{equation}
This represents the total discounted reward accumulated starting from $s_t$.

The state-value function $V^\pi(s)$ under policy $\pi$ is the expected return starting from state $s$:
\begin{equation}
V^\pi(s) = \mathbb{E}_\pi[G_t | s_t = s].
\end{equation}
Similarly, the action-value function $Q^\pi(s,a)$ is the expected return after taking action $a$ in state $s$ and then following $\pi$.

In actor-critic methods, we parameterize the policy as $\pi_\theta(a|s)$, where $\theta$ are the policy parameters, and the value function as $V_\phi(s)$, where $\phi$ are the value parameters.

The advantage function $A^\pi(s,a)$ measures how much better action $a$ is compared to the average action in state $s$:
\begin{equation}
A^\pi(s,a) = Q^\pi(s,a) - V^\pi(s).
\end{equation}
In practice, we approximate this using temporal difference (TD) estimates:
\begin{equation}
A_t \approx r_t + \gamma V_\phi(s_{t+1}) - V_\phi(s_t),
\end{equation}
which is a one-step TD error. This approximation reduces variance compared to using the full return $G_t$.

\subsection{Parameterized Policies and Value Functions}
For continuous action spaces or stochastic policies, we often use parameterized distributions. In this report, we assume discrete actions with a categorical policy $\pi_\theta(a|s) = \frac{\exp(\logits_a)}{\sum_{a'} \exp(\logits_{a'})}$, where $logits$ are outputs from a neural network.

The value function $V_\phi(s)$ is approximated by a neural network that takes state $s$ as input and outputs a scalar value estimate.
\section{A2C Objective and Derivation}
This section derives the A2C objective function step-by-step, building on the policy gradient theorem and introducing the advantage baseline.

\subsection{Policy Gradient Theorem}
The policy gradient theorem provides a way to optimize the policy parameters $\theta$ to maximize the expected return $J(\theta) = \mathbb{E}_{\pi_\theta}[G_0]$. Using the log-derivative trick, we can express the gradient as:
\begin{equation}
\nabla_\theta J(\theta) = \mathbb{E}_{\pi_\theta} \left[ \sum_t \nabla_\theta \log \pi_\theta(a_t | s_t) G_t \right].
\end{equation}
This is the REINFORCE algorithm, but it suffers from high variance because $G_t$ can be noisy.

\subsection{Introducing the Advantage Baseline}
To reduce variance, we subtract a baseline $b(s_t)$ from the return, which does not change the expectation since $\mathbb{E}[\nabla_\theta \log \pi_\theta(a_t|s_t)] = 0$:
\begin{equation}
\nabla_\theta J(\theta) = \mathbb{E}_{\pi_\theta} \left[ \sum_t \nabla_\theta \log \pi_\theta(a_t | s_t) (G_t - b(s_t)) \right].
\end{equation}
Choosing $b(s_t) = V_\phi(s_t)$, the state-value function, gives the advantage $A_t = G_t - V_\phi(s_t)$. This leads to the actor-critic objective:
\begin{equation}
\nabla_\theta J(\theta) = \mathbb{E}_{\pi_\theta} \left[ \sum_t \nabla_\theta \log \pi_\theta(a_t | s_t) A_t \right].
\end{equation}

\subsection{Entropy Regularization}
To encourage exploration and prevent premature convergence to suboptimal policies, we add an entropy bonus to the policy loss:
\begin{equation}
L_{\text{policy}} = -\mathbb{E} [\log \pi_\theta(a_t | s_t) A_t] - \beta H[\pi_\theta(\cdot | s_t)],
\end{equation}
where $H[\pi] = -\sum_a \pi(a|s) \log \pi(a|s)$ is the entropy of the policy distribution, and $\beta > 0$ is the entropy coefficient.

\subsection{Value Function Loss}
The critic is trained to minimize the mean squared error between the predicted value $V_\phi(s_t)$ and the target return $G_t$:
\begin{equation}
L_{\text{value}} = \mathbb{E} [(V_\phi(s_t) - G_t)^2].
\end{equation}

\subsection{Total A2C Loss}
The combined loss function is:
\begin{equation}
L = L_{\text{policy}} + c_v L_{\text{value}},
\end{equation}
where $c_v > 0$ weights the value loss relative to the policy loss. In practice, gradient clipping is applied to stabilize training.
\section{Algorithm (pseudocode)}
The A2C algorithm operates in an episodic or step-based loop, collecting rollouts from the environment and updating the actor and critic networks. Below is a detailed pseudocode description.

\begin{algorithm}[H]
\caption{Advantage Actor-Critic (A2C) Algorithm}
\label{alg:a2c}
\begin{algorithmic}[1]
\State \textbf{Input:} Environment $\mathcal{E}$, number of parallel environments $N$, rollout length $T$, total timesteps $T_{\text{max}}$, discount $\gamma$, entropy coefficient $\beta$, value coefficient $c_v$, learning rate $\alpha$, gradient clip norm $c_g$
\State Initialize actor parameters $\theta$ and critic parameters $\phi$ (e.g., random initialization)
\State Initialize optimizer (e.g., Adam with learning rate $\alpha$)
\State $t \gets 0$  \Comment{Global timestep counter}
\While{$t < T_{\text{max}}$}
  \State Collect rollouts: For each of $N$ parallel environments, run $T$ steps:
  \For{each environment $i = 1$ to $N$}
    \State Reset environment and get initial state $s_0^i$
    \For{step $k = 0$ to $T-1$}
      \State Sample action $a_k^i \sim \pi_\theta(\cdot | s_k^i)$
      \State Execute action, observe reward $r_k^i$ and next state $s_{k+1}^i$
      \State Store transition $(s_k^i, a_k^i, r_k^i, s_{k+1}^i)$
    \EndFor
  \EndFor
  \State Compute returns and advantages for each rollout:
  \For{each rollout $i$}
    \State Bootstrap final value: $V_{\text{next}} \gets V_\phi(s_T^i)$ if not terminal, else 0
    \State Compute discounted returns $G_k^i$ backwards from $k=T-1$ to 0:
    \State $G_T^i \gets V_{\text{next}}$
    \For{$k = T-1$ downto 0}
      \State $G_k^i \gets r_k^i + \gamma G_{k+1}^i$
    \EndFor
    \State Compute advantages: $A_k^i \gets G_k^i - V_\phi(s_k^i)$
  \EndFor
  \State Flatten all rollouts into a batch of size $N \times T$
  \State Compute policy loss: $L_{\text{policy}} \gets -\frac{1}{N T} \sum \log \pi_\theta(a | s) \cdot A - \beta \cdot H[\pi_\theta(\cdot | s)]$
  \State Compute value loss: $L_{\text{value}} \gets \frac{1}{N T} \sum (V_\phi(s) - G)^2$
  \State Total loss: $L \gets L_{\text{policy}} + c_v L_{\text{value}}$
  \State Compute gradients: $\nabla_\theta L, \nabla_\phi L$
  \State Clip gradients: $\nabla \gets \min(1, c_g / \|\nabla\|) \cdot \nabla$
  \State Update parameters: $\theta \gets \theta - \alpha \nabla_\theta L$, $\phi \gets \phi - \alpha \nabla_\phi L$
  \State $t \gets t + N \times T$
\EndWhile
\State \textbf{Output:} Trained policy $\pi_\theta$ and value function $V_\phi$
\end{algorithmic}
\end{algorithm}

This pseudocode highlights the synchronous nature of A2C: all environments run in parallel, but updates are performed after collecting all rollouts. The rollout length $T$ controls the trade-off between bias (shorter rollouts) and variance (longer rollouts). In our implementation, we use $T=5$ for simplicity, but in practice, $T$ can be tuned based on the environment.
\section{Architecture and Implementation Details}
This section describes the neural network architecture, implementation choices, and key components of our A2C code.

\subsection{Neural Network Architecture}
The actor-critic network consists of a shared encoder followed by separate actor and critic heads. This shared architecture promotes parameter efficiency and allows the network to learn joint representations of states.

\begin{itemize}
  \item \textbf{Shared Encoder:} A multi-layer perceptron (MLP) with two hidden layers, each containing 128 units and ReLU activations. The input is the state vector (e.g., 4-dimensional for CartPole), and the output is a 128-dimensional feature vector.
  \item \textbf{Actor Head:} A linear layer that maps the shared features to action logits. For discrete actions, the logits are fed into a softmax to produce a categorical distribution.
  \item \textbf{Critic Head:} A linear layer that maps the shared features to a scalar value estimate.
\end{itemize}

The network is implemented in PyTorch using \texttt{nn.Sequential} for modularity. Weights are initialized using PyTorch's default initialization (Xavier for linear layers), and biases are set to zero.

\subsection{Implementation Choices}
\begin{itemize}
  \item \textbf{Language and Framework:} Python 3.10+ with PyTorch for neural networks and NumPy for numerical computations. This choice ensures compatibility with modern RL libraries and GPU acceleration.
  \item \textbf{Environment Interface:} We use Gymnasium (formerly OpenAI Gym) for environment interactions. States are converted to PyTorch tensors, and actions are sampled from the policy distribution.
  \item \textbf{Data Structures:} Rollouts are stored as dictionaries of lists (e.g., \texttt{rollouts["states"]} contains a list of state tensors). This allows efficient batching during updates.
  \item \textbf{Device Management:} The code supports CPU and GPU execution via PyTorch's device abstraction. CUDA determinism is enabled where possible.
  \item \textbf{Seeding and Reproducibility:} All random operations (environment resets, action sampling, network initialization) are seeded using a centralized \texttt{set\_seed} function.
\end{itemize}

\subsection{Key Modules}

\section{Discussion}
The A2C algorithm represents a robust baseline for actor-critic reinforcement learning, effectively combining policy optimization with value function estimation to achieve stable and sample-efficient training. Our implementation demonstrates the practical application of these theoretical concepts, providing insights into the interplay between exploration, exploitation, and learning dynamics.

\subsection{Key Insights from Implementation}
The shared encoder architecture promotes efficient learning by allowing the network to capture common features for both policy and value prediction. Entropy regularization proves crucial for maintaining exploration in deterministic environments like CartPole, preventing the agent from converging to suboptimal policies too early. Gradient clipping adds stability, particularly in the early stages of training when gradients can be large.

The bandit example underscores the importance of incremental updates and exploration strategies in simpler settings. It serves as a controlled environment for testing algorithmic components without the complexity of full RL environments.

\subsection{Comparison to Related Methods}
Compared to vanilla policy gradients (e.g., REINFORCE), A2C's advantage baseline significantly reduces variance, leading to smoother learning curves and faster convergence. Unlike off-policy methods like SAC, A2C is on-policy and requires fresh data per update, making it less sample-efficient but easier to implement and tune.

A2C improves upon A3C by eliminating asynchronous updates, which can introduce instability due to parameter staleness. This synchronous approach simplifies debugging and ensures deterministic behavior across runs.

\subsection{Implications and Broader Impact}
Actor-critic methods like A2C have broad applications in robotics, game AI, and autonomous systems. By learning both a policy and a value function, agents can make informed decisions in complex, uncertain environments. However, care must be taken to ensure ethical deployment, as RL agents can exhibit unintended behaviors if not properly constrained.

This implementation contributes to the open-source RL community by providing a clean, well-documented codebase that can serve as a starting point for advanced research. It emphasizes reproducibility, a critical aspect often overlooked in RL papers.

\subsection{Future Directions}
Extending A2C to continuous action spaces, hierarchical policies, or multi-agent settings could yield powerful generalizations. Integrating with modern techniques like generalized advantage estimation or proximal policy optimization would further enhance performance and stability.

\section{Limitations and Future Work}
While our A2C implementation provides a solid foundation, several limitations and opportunities for improvement exist.

\subsection{Limitations}
\begin{itemize}
  \item \textbf{Sample Efficiency:} As an on-policy method, A2C requires fresh data for each update, making it less efficient than off-policy algorithms in data-scarce scenarios.
  \item \textbf{Environment Scalability:} The current implementation assumes discrete actions and vectorized states. Extensions to continuous actions or image inputs would require modifications.
  \item \textbf{Hyperparameter Sensitivity:} RL algorithms are notoriously sensitive to hyperparameters. While we provide defaults, extensive tuning may be needed for new environments.
  \item \textbf{Parallelization:} Although designed for parallel environments, the notebook implementation may not fully leverage this for simplicity.
  \item \textbf{Evaluation:} Our evaluation focuses on episodic rewards; more comprehensive metrics (e.g., regret, robustness to perturbations) could provide deeper insights.
\end{itemize}

\subsection{Future Work}
\begin{itemize}
  \item \textbf{Algorithmic Improvements:} Implement Generalized Advantage Estimation (GAE) for better advantage estimation. Explore PPO-style clipped objectives for improved stability.
  \item \textbf{Architecture Enhancements:} Add recurrent layers for partially observable environments or attention mechanisms for multi-modal inputs.
  \item \textbf{Experimental Extensions:} Conduct large-scale experiments on benchmark suites like MuJoCo or Atari. Include multi-agent variants for cooperative/competitive settings.
  \item \textbf{Software Engineering:} Develop a full experiment harness with logging, checkpointing, and hyperparameter optimization. Integrate with tools like Weights \& Biases for tracking.
  \item \textbf{Theoretical Analysis:} Provide convergence guarantees or regret bounds for the implemented algorithm.
  \item \textbf{Applications:} Apply to real-world problems like robotic control or recommendation systems, adapting the code as needed.
\end{itemize}

Addressing these limitations would make the implementation more versatile and impactful.

\section{Appendix H: Glossary}
\begin{itemize}
  \item \textbf{Actor:} The policy component in actor-critic methods, responsible for action selection.
  \item \textbf{Advantage Function:} Measures how much better an action is than the average action in a state.
  \item \textbf{Critic:} The value function component, estimating state or state-action values.
  \item \textbf{Discount Factor ($\gamma$):} Weights future rewards relative to immediate ones.
  \item \textbf{Entropy:} A measure of randomness in the policy distribution; higher entropy encourages exploration.
  \item \textbf{Episode:} A complete sequence of interactions from start to terminal state.
  \item \textbf{Markov Decision Process (MDP):} A mathematical framework for sequential decision-making.
  \item \textbf{On-Policy:} Learning methods that use data from the current policy.
  \item \textbf{Policy Gradient:} Optimization technique for parameterized policies using gradient ascent.
  \item \textbf{Return ($G_t$):} The total discounted reward from time $t$ onward.
  \item \textbf{Rollout:} A trajectory of state-action-reward transitions collected from the environment.
  \item \textbf{State-Value Function ($V$):} Expected return from a state under a policy.
  \item \textbf{Temporal Difference (TD) Learning:} Method for estimating value functions using bootstrapping.
\end{itemize}

\section{Appendix A: Derivation of the Policy Gradient}
We summarize a standard derivation of the policy gradient used by policy
gradient and actor-critic methods. Consider the expected discounted return
under policy $\pi_\theta$:
\begin{equation}
J(\theta) = \mathbb{E}_\theta\left[\sum_{t=0}^\infty \gamma^t r_t\right].
\end{equation}
Using the log-derivative trick and marginalizing over trajectories, we obtain
\begin{align}
\nabla_\theta J(\theta) &= \nabla_\theta \mathbb{E}_\theta\left[\sum_t \gamma^t r_t\right]
= \sum_t \mathbb{E}_\theta\left[\gamma^t r_t \nabla_\theta \log \pi_\theta(\tau)\right] \\
&= \sum_t \mathbb{E}_\theta\left[ \nabla_\theta \log \pi_\theta(a_t|s_t) G_t \right]
= \mathbb{E}_\theta\left[\sum_t \nabla_\theta \log \pi_\theta(a_t|s_t) G_t\right],
\end{align}
where $G_t$ is the return from time $t$ and we used trajectory factorization.
Subtracting a baseline $b(s_t)$ yields an equivalent (lower-variance) estimator:
\begin{equation}
\nabla_\theta J(\theta) = \mathbb{E}_\theta\left[\sum_t \nabla_\theta \log \pi_\theta(a_t|s_t) (G_t - b(s_t))\right].
\end{equation}
Choosing $b(s_t) = V_\phi(s_t)$ and estimating advantages $A_t = G_t - V_\phi(s_t)$
leads to the actor update used in A2C.

\section{Appendix B: Generalized Advantage Estimation (GAE)}
Generalized Advantage Estimation (GAE) trades off bias and variance in
advantage estimation using a parameter $\lambda\in[0,1]$ \cite{schulman2015high}. Define
\begin{align}
\delta_t &= r_t + \gamma V_\phi(s_{t+1}) - V_\phi(s_t), \\
A^{\text{GAE}(\gamma,\lambda)}_t &= \sum_{l=0}^{\infty} (\gamma\lambda)^l \delta_{t+l}.
\end{align}
GAE is implemented by bootstrapping with the value function and exponentially
weighting temporal difference residuals; setting $\lambda=1$ recovers Monte-Carlo
returns, while $\lambda=0$ uses one-step TD errors.

\section{Appendix C: Algorithm pseudocode}
\begin{algorithm}[h]
\caption{Synchronous A2C (single-process, multi-step rollouts)}
\begin{algorithmic}[1]
\STATE Initialize policy and value networks $\theta, \phi$
\FOR{each iteration}
  \STATE Collect $T$ steps of experience: $(s_t,a_t,r_t,s_{t+1},d_t)$
  \STATE Compute bootstrapped returns $G_t$ using $V_\phi(s_{t+1})$
  \STATE Compute advantages $A_t = G_t - V_\phi(s_t)$
  \STATE Update actor: minimize $-\sum_t \log\pi_\theta(a_t|s_t) A_t - \beta H[\pi_\theta]$
  \STATE Update critic: minimize $\sum_t (V_\phi(s_t) - G_t)^2$
  \STATE Perform gradient clipping and optimizer step
\ENDFOR
\end{algorithmic}
\end{algorithm}

\section{Statistical Analysis and Reporting}
To report experimental results rigorously, follow these practices:
\begin{itemize}
  \item For each experimental condition run multiple seeds (e.g., 5) and report mean $\pm$ standard error of the mean (SEM):
    \begin{equation}
      \text{SEM} = \frac{\sigma}{\sqrt{n}}, \quad CI_{95\%} = \bar{x} \pm 1.96\cdot\text{SEM}.
    \end{equation}
  \item When comparing two algorithms, use paired tests across seeds (e.g., paired t-test if approximate normality holds). For non-normal reward distributions, use non-parametric tests like Wilcoxon signed-rank test or bootstrap the difference in means.
  \item Report effect sizes (Cohen's d) and 95\% confidence intervals, not only p-values. Use visualization (e.g., learning curves with shaded CI, violin plots for final returns) to show variance across seeds.
\end{itemize}

\subsection{Actor-Critic Model}
\begin{lstlisting}[caption=Actor-Critic neural network model]
import torch
import torch.nn as nn

class ActorCritic(nn.Module):
    def __init__(self, num_inputs, num_outputs, hidden_size=128):
        super().__init__()
        self.shared = nn.Sequential(
            nn.Linear(num_inputs, hidden_size),
            nn.ReLU(),
            nn.Linear(hidden_size, hidden_size),
            nn.ReLU(),
        )
        self.actor = nn.Linear(hidden_size, num_outputs)
        self.critic = nn.Linear(hidden_size, 1)

    def forward(self, x):
        shared_out = self.shared(x)
        action_logits = self.actor(shared_out)
        value = self.critic(shared_out)
        return action_logits, value
\end{lstlisting}

\subsection{A2C Agent Update}
\begin{lstlisting}[caption=A2C agent update method]
def update(self, rollouts):
    states = torch.stack(rollouts["states"])
    actions = torch.stack(rollouts["actions"])
    old_log_probs = torch.stack(rollouts["log_probs"])
    old_values = torch.stack(rollouts["values"])
    rewards = rollouts["rewards"]
    dones = rollouts["dones"]

    returns = self.compute_returns(rewards, dones, next_value)
    advantages = returns - old_values.squeeze()

    action_logits, values = self.model(states)
    dist = Categorical(logits=action_logits)
    new_log_probs = dist.log_prob(actions)
    entropy = dist.entropy()

    policy_loss = -(new_log_probs * advantages.detach()).mean()
    value_loss = nn.MSELoss()(values.squeeze(), returns)
    entropy_loss = -entropy.mean()

    total_loss = policy_loss + self.value_coef * value_loss + self.entropy_coef * entropy_loss

    self.optimizer.zero_grad()
    total_loss.backward()
    nn.utils.clip_grad_norm_(self.model.parameters(), self.max_grad_norm)
    self.optimizer.step()

    return {
        "total_loss": total_loss.item(),
        "policy_loss": policy_loss.item(),
        "value_loss": value_loss.item(),
        "entropy_loss": entropy_loss.item(),
    }
\end{lstlisting}
