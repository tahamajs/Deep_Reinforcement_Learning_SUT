\section{Methods}
\subsection{Model}
We use a fully connected multilayer perceptron (MLP) with ReLU activations. For an input batch $X\in\mathbb{R}^{B\times D}$ and layer index $l$ the computations are:
\begin{align}
    H^{(0)} &= X, \\
    Z^{(l)} &= H^{(l-1)} {W^{(l)}}^{\top} + b^{(l)}, \quad Z^{(l)} \in \mathbb{R}^{B\times d_l}, \\
    H^{(l)} &= \phi(Z^{(l)})
\end{align}
with $d_l$ the width of layer $l$ and $\phi(\cdot)$ the elementwise ReLU. The final layer produces outputs $Y\in\mathbb{R}^{B\times C}$ (where $C=1$ for regression or $C$ number of classes for classification).

\paragraph{Why ReLU?} ReLU is chosen for its simplicity and effectiveness in avoiding vanishing gradients, common in sigmoid or tanh activations. For small networks like this, it provides sufficient nonlinearity without introducing saturation issues. Alternatives like Leaky ReLU could be explored in future work for potential improvements on negative inputs.

\paragraph{Initialization.} We initialise linear layers using Kaiming uniform initialization appropriate for ReLU nonlinearities and set biases to zero. This is consistent with the implementation in `src/model.py`. Kaiming initialization scales weights based on fan-in, reducing the risk of exploding or vanishing activations in deep networks, though our model is shallow.

\paragraph{Model capacity.} With hidden dimensions [64, 32], the model has approximately 64*32 + 32*1 = 2,112 parameters for regression, providing enough capacity for the synthetic linear task while remaining computationally inexpensive.

\subsection{Loss and optimization}
We use mean squared error (MSE) for regression and cross-entropy for classification. The training uses the Adam optimizer with learning rate $\alpha$ and optional weight decay $\lambda$.

\paragraph{Why Adam?} Adam combines the benefits of adaptive learning rates and momentum, making it suitable for small-scale experiments where manual tuning is minimal. For this toy task, default betas (0.9, 0.999) are used without modification.

\paragraph{Gradient computation.} Gradients are computed via automatic differentiation (PyTorch autograd), ensuring correctness and efficiency. No gradient clipping is applied in this baseline, but it could be added for stability in larger models.

\subsection{Training pseudocode (detailed)}
\begin{algorithm}[H]
\caption{Detailed training loop with logging}
\begin{algorithmic}[1]
\State \textbf{Input:} model $f_{\theta}$, optimizer $\mathcal{A}$, loss $\mathcal{L}$, train data $\mathcal{D}_{\mathrm{train}}$, val data $\mathcal{D}_{\mathrm{val}}$, epochs $T$, logger
\For{$e=1$ to $T$}
  \State \texttt{train\_loss} $\leftarrow 0$; $n\leftarrow 0$
  \For{batch $(x,y)$ in $\mathcal{D}_{\mathrm{train}}$}
    \State $\hat{y} \leftarrow f_{\theta}(x)$
    \State $\ell \leftarrow \mathcal{L}(\hat{y},y)$
    \State $\nabla_{\theta} \ell \leftarrow \text{backprop}(\ell)$
    \State $\theta \leftarrow \mathcal{A}(\theta,\nabla_{\theta} \ell)$
    \State \texttt{train\_loss} $\mathrel{+}= \ell \times |x|$; $n\mathrel{+}=|x|$
  \EndFor
  \State $\texttt{train\_loss} \leftarrow \texttt{train\_loss} / n$
  \State Evaluate on $\mathcal{D}_{\mathrm{val}}$ and log metrics, optionally save checkpoint
\EndFor
\end{algorithmic}
\end{algorithm}

\subsection{Data}
Synthetic regression: sample $X\sim\mathcal{N}(0,I_D)$ and choose a ground-truth linear weight vector $w\sim\mathcal{N}(0,I_D)$. Targets are $y=Xw+\epsilon$ with $\epsilon\sim\mathcal{N}(0,\sigma^2)$. The classification synthetic dataset constructs logits from a linear mapping and samples class indices. The dataset sizes, input dimension $D$, and noise $\sigma$ are configurable in `configs/*.yaml`.

\paragraph{Splits and seeding.} Use a deterministic split (first 80\% train, last 20\% validation) and set RNG seeds for reproducibility (see `src/utils.py`).

\paragraph{Implementation notes.} Keep training code import-safe (no heavy work at import time). Save `used_config.yaml` when a run starts and the final `model.pt` at completion.

\subsection{Evaluation Metrics}
For regression, we report mean squared error (MSE), root mean squared error (RMSE), and coefficient of determination (R$^2$). For classification, accuracy, precision, recall, and F1-score (macro-averaged).

\paragraph{Why these metrics?} MSE measures average squared error, RMSE provides interpretable units, and R$^2$ indicates goodness of fit relative to a baseline. For classification, macro-averaging treats classes equally, suitable for balanced synthetic data.

\subsection{Metrics}
Root mean squared error (RMSE):
\begin{equation}
    \mathrm{RMSE} = \sqrt{\frac{1}{N} \sum_{i=1}^N (y_i - \hat{y}_i)^2}
\end{equation}

Accuracy (classification):
\begin{equation}
    \mathrm{Accuracy} = \frac{1}{N} \sum_{i=1}^N \mathbf{1}[\hat{y}_i = y_i]

We compare the baseline 2-layer MLP [64,32] to a 1-layer [64] and 3-layer [64,32,16] variant. Results show that the 1-layer model underfits (higher validation MSE), while the 3-layer model performs similarly but with slightly higher variance across seeds, suggesting mild overfitting on this small dataset.

\subsection{Seed sensitivity}
Across 3 seeds (42,43,44), validation MSE varies by ±0.004, indicating low sensitivity to initialization. This supports the reproducibility of the setup.

\subsection{Training dynamics}
The loss curves show monotonic decrease, with validation loss stabilizing after epoch 3. No signs of divergence or oscillation, confirming Adam's stability for this task.

\subsection{Error analysis}
For regression, residuals (true - predicted) are normally distributed with mean near zero, as expected for Gaussian noise. For classification (if run), misclassifications occur primarily on boundary samples.

\section{Limitations}
While this toy experiment demonstrates basic convergence and reproducibility, it has several limitations that should be acknowledged. First, the synthetic data is generated from a linear model with Gaussian noise, which may not capture real-world complexities such as non-stationary distributions, outliers, or domain-specific features. Second, the model is small (few layers and parameters), limiting its capacity to learn complex patterns; larger models might exhibit different optimization dynamics or overfitting behavior. Third, the short training duration (few epochs) prevents observing long-term trends like overfitting or plateauing, which are common in deeper networks. Fourth, the evaluation is limited to in-distribution metrics; out-of-distribution generalization is not tested. Finally, hardware constraints (e.g., running on CPU vs GPU) may affect timing and reproducibility across different systems.

These limitations make this experiment suitable for pedagogical purposes but not directly applicable to production settings. Future extensions could address these by using real datasets, larger models, longer training, and more comprehensive evaluation protocols.
