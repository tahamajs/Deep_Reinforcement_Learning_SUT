\begin{abstract}
This document is the complete technical report for AMASA-Complex v2. It unifies deep reinforcement learning theory, constrained optimization, system architecture, implementation details, and reproducible empirical analysis for a safety-critical autonomous suturing benchmark. The project extends the baseline assignment into a full course-scale platform by integrating four algorithms (CQL, IQL, SAC-Lagrangian, PPO-Lagrangian), a hybrid safety stack (PID dual controller, decision-tree shield, trajectory risk critic), scenario-based robustness evaluation (nominal, perturbed, adversarial), and config-driven orchestration with backward-compatible command line interfaces.

The report has three goals. First, it explains the conceptual foundations needed to understand why each module exists and what failure mode it addresses. Second, it documents the implementation choices made in the codebase, including configuration semantics, reproducibility contracts, logging standards, and compatibility constraints. Third, it presents benchmark and PID-sweep results generated from the local pipeline and interprets them through the reward-safety Pareto lens instead of a single scalar metric.

The key conclusion is that offline pretraining can produce strong starter policies under limited compute, but safe online adaptation remains the dominant difficulty. Hybrid guard instrumentation and expanded PID sweeps improve diagnostic clarity and can improve frontier location, but strong safety performance requires careful coordination of data coverage, dual control tuning, and scenario curriculum.
\end{abstract}

\section{Introduction and Problem Context}
Autonomous surgical assistance is an attractive domain for advanced reinforcement learning education because it forces students to solve coupled problems rather than isolated ones. In a single benchmark, students must formalize dynamics, deal with high-dimensional observations, train policies under sparse success criteria, and guarantee safety in the presence of uncertainty. This coupling is precisely what is often missing in smaller RL assignments that focus only on maximizing reward in benign simulators.

AMASA-Complex v2 addresses this pedagogical and engineering gap. The project is intentionally organized around the complete development lifecycle: offline initialization, constrained online improvement, robustness stress testing, and interpretability-oriented safety enforcement. In practical terms, students do not just train an agent; they design an operational stack where policy learning, guard logic, logging, evaluation, and reporting interact under explicit reproducibility constraints.

The importance of this structure becomes clear when one examines where failures occur in real implementations. Many RL pipelines fail not because the algorithmic formula is wrong, but because surrounding engineering assumptions break: inconsistent checkpoint metadata, hidden config precedence bugs, no clear separation between scenario overlays, or missing safety telemetry. AMASA-Complex v2 treats these as first-class technical concerns and includes mechanisms to expose and control them.

\section{Mathematical Foundations}
\subsection{MDP and CMDP Formulation}
The base learning problem is modeled as an MDP $\mathcal{M}=(\mathcal{S},\mathcal{A},P,R,\gamma)$. A policy $\pi(a\mid s)$ induces trajectories $\tau=(s_0,a_0,s_1,\dots)$ and maximizes expected discounted return:
\[
J_R(\pi)=\mathbb{E}_{\tau\sim\pi}\left[\sum_{t=0}^{\infty}\gamma^t r_t\right].
\]
In safety-critical domains we extend to CMDP by introducing cost $c_t$ and limit $d$:
\[
\max_{\pi} J_R(\pi)\quad\text{s.t.}\quad J_C(\pi)=\mathbb{E}_{\tau\sim\pi}\left[\sum_{t=0}^{\infty}\gamma^t c_t\right]\le d.
\]

A Lagrangian relaxation yields:
\[
\mathcal{L}(\pi,\lambda)=J_R(\pi)-\lambda\left(J_C(\pi)-d\right),\quad \lambda\ge0.
\]
While this relaxation is standard, practical training behavior depends heavily on how $\lambda$ is updated and how quickly cost estimators calibrate under distribution shift.

\subsection{Offline RL Under Distribution Shift}
Given a static dataset $\mathcal{D}$ collected by behavior policy $\pi_\beta$, offline RL must avoid optimistic extrapolation on unseen actions. Conservative methods (e.g., CQL) explicitly penalize high Q-values on out-of-distribution actions. Implicit methods (e.g., IQL) avoid explicit behavior density ratios and instead rely on value-weighted policy extraction. Both approaches trade policy improvement speed for robustness against false value peaks.

\subsection{Safety-Driven Control Perspective}
Safety in online adaptation can be interpreted as a control problem over the dual variable. If the violation error is $e_t = c_t - d$, then dual update dynamics can be written as proportional-integral-derivative control:
\[
\lambda_{t+1}=\mathrm{clip}\left(K_p e_t + K_i\sum_{\tau\le t}e_\tau + K_d(e_t-e_{t-1}),\,0,\,\lambda_{\max}\right).
\]
This representation clarifies why gain tuning is central to practical safe RL behavior: the wrong gains cause oscillation or over-conservative lock-in.

\section{Algorithmic Components}
\subsection{CQL}
CQL augments temporal-difference regression with conservative penalties over sampled actions to suppress unsupported value spikes. In practice this provides safer startup behavior when online exploration is still expensive or risky.

\subsection{IQL}
IQL separates value fitting and policy extraction. The value network is trained via expectile regression, then the actor is trained with advantage-weighted targets. This often yields stable offline policies without aggressive policy-constraint engineering.

\subsection{SAC-Lagrangian}
SAC-Lagrangian in this project maintains reward and cost critics and updates actor parameters against entropy-regularized reward minus dual-weighted cost estimate. The method is replay-efficient and suitable for CPU-first iterative experimentation.

\subsection{PPO-Lagrangian}
PPO-Lagrangian uses clipped updates with separate reward and cost advantages. It is included to expose students to on-policy constrained optimization and to contrast replay-based versus trajectory-based adaptation behavior.

\section{Hybrid Safety Guard Design}
\subsection{Guard Ordering}
At each step:
\begin{enumerate}[leftmargin=*]
  \item policy proposes action,
  \item risk critic scores $(s,a,h)$,
  \item risky actions receive conservative transformation,
  \item decision-tree shield applies explicit allow/deny logic,
  \item environment executes final action,
  \item PID controller updates $\lambda$ from observed cost.
\end{enumerate}

\subsection{Rationale}
This order intentionally combines statistical prediction and symbolic constraints. Statistical modules adapt with data; rule modules provide direct interpretability. Their combination is more robust than either alone in early online phases where value estimates are still moving.

\section{Software Architecture and Reproducibility}
\subsection{Module Layout}
The project introduces structured packages for config, environment, algorithms, safety, benchmarking, and scripts. The design keeps legacy script entrypoints functional while exposing a unified runner for matrix experiments.

\subsection{Configuration Contract}
YAML overlays define base settings, algorithm-specific parameters, scenario perturbations, runtime presets, sweep grids, and acceptance thresholds. Merge order is deterministic and validated. This eliminates a class of hidden experiment drift bugs.

\subsection{Backward Compatibility}
Legacy scripts continue to work with old flags. Optional flags (\texttt{--config}, \texttt{--preset}, \texttt{--scenario}, \texttt{--algo}) extend functionality without breaking previous workflows.

\section{Detailed Implementation Walkthrough}
\subsection{Configuration and Schema}
The configuration loader validates required top-level sections and legal enum values. Overlay application is explicit, and tests verify that smoke preset runtime settings remain effective after algorithm/scenario overlays. This addresses a subtle but common source of reproducibility regressions.

\subsection{Pipeline and Runner Behavior}
The runner now supports resumable matrix execution by skipping jobs that already have summary outputs. This is especially important for long sweeps and storage-constrained environments. Final-only checkpoint saving in benchmark/sweep modes reduces disk pressure while preserving end-state reproducibility.

\subsection{Safety Logging and Plotting}
Online training exports step-level safety records and renders timeline plots. Aggregation scripts now generate global Pareto plots, per-scenario curves, PID heatmaps (reward/cost/frontier), and best-run safety timeline figures.

\subsection{Serializer Robustness}
A fallback serializer path is implemented for environments where zip-based torch serialization can fail under storage pressure. This avoids interrupted long-run sweeps and supports robust checkpoint finalization.

\section{Ablation Blueprint for Full Preset}
For course delivery, we recommend the following ablation matrix in full preset runs:
\begin{enumerate}[leftmargin=*]
  \item Remove risk critic gate, keep shield and PID.
  \item Remove shield, keep risk gate and PID.
  \item Replace PID with vanilla dual ascent.
  \item Disable scenario randomization in online phase.
  \item Compare CQL versus IQL warm-start for each online algorithm.
\end{enumerate}
Each ablation should be evaluated across the same seeds and scenarios with identical thresholds. The expected output is not only score deltas but also behavior-trace differences (lambda saturation frequency, block rate dynamics, risk score calibration drift).

\section{Recommended Next Iteration Plan}
Based on current results, a practical next cycle is:
\begin{itemize}[leftmargin=*]
  \item Increase offline warm-start steps for IQL/CQL under fixed replay sampling.
  \item Introduce phase-wise cost limits to avoid early lock-in during online startup.
  \item Use best PID regions from expanded sweep as warm defaults.
  \item Add critic calibration diagnostics (reward-cost scale alignment).
  \item Run full preset for top frontier configurations only to control compute budget.
\end{itemize}

AMASA-Complex v2 now operates as a complete and technically rigorous RL project that spans theory, implementation, safety, and reproducible evaluation. The code and report together provide a strong template for advanced coursework and project-based research training. The current smoke results are intentionally realistic: offline initialization is strong, while safe online adaptation remains challenging. This is precisely the educational value of the benchmark, and the added tooling makes those challenges measurable, diagnosable, and improvable.
