\begin{abstract}
This report presents AMASA-Complex v2, a major upgrade of the original AMASA suturing assignment into an advanced course-scale reinforcement learning (RL) system. The implementation introduces: (1) a four-method algorithm suite (CQL, IQL, SAC-Lagrangian, PPO-Lagrangian), (2) a hybrid runtime safety stack (PID dual control, decision-tree shield, and trajectory risk critic), (3) three environment scenario families (nominal, perturbed, adversarial), (4) YAML-first experiment composition with backward-compatible legacy CLIs, and (5) automated benchmark and PID-grid evaluation pipelines. The project is CPU-first and keeps old commands functional while adding a unified experiment entrypoint. We report full smoke-preset benchmark and expanded PID sweep outcomes, including Pareto analysis, safety timeline diagnostics, and tiered threshold checks.
\end{abstract}

\section{Introduction}
Modern RL education increasingly requires students to reason about offline data leverage, online adaptation, and strict safety constraints under non-stationary conditions. Isolated assignments are usually strong on one axis and weak on the others. AMASA-Complex v2 is designed to close this gap by combining the full chain in one implementation:
\begin{itemize}[leftmargin=*]
  \item offline pretraining with conservative objectives,
  \item online constrained improvement with safety feedback,
  \item robustness pressure via scenario variation and corruption,
  \item explainable intervention through rule-based shielding.
\end{itemize}

Compared with the previous baseline, v2 adds algorithmic diversity, richer safety instrumentation, standardized configuration and orchestration, and testable acceptance criteria. The goal is not only higher reward, but also reproducible reward--cost trade-off analysis and practical failure diagnosis.

\section{System Architecture}
\subsection{Core Runtime Layers}
AMASA-Complex v2 uses a layered architecture:
\begin{itemize}[leftmargin=*]
  \item \textbf{Config layer}: deterministic merge and validation of YAML overlays.
  \item \textbf{Environment layer}: shared suturing dynamics and scenario wrappers.
  \item \textbf{Learning layer}: offline and online algorithms with common interfaces.
  \item \textbf{Safety layer}: hybrid guard composing statistical and symbolic checks.
  \item \textbf{Evaluation layer}: matrix runners, aggregation, plotting, threshold gates.
\end{itemize}

The architecture intentionally separates concerns so that students can swap algorithms or scenario stressors without rewriting orchestration code.

\subsection{Config and Overlay Order}
A key reliability change is explicit overlay order:
\[
\text{base} \rightarrow \text{scenario} \rightarrow \text{algorithm} \rightarrow \text{preset}
\]
Applying preset last ensures smoke/full runtime envelopes remain stable even when algorithm YAMLs define larger step counts.

\subsection{Registry and Extensibility}
Simple registries are added for environment, algorithm, and safety components. This enables factory-based instantiation by name and avoids hard-coded class branching across scripts.

\section{Environment and Scenario Modeling}
\subsection{State, Action, Reward, Cost}
The suturing environment preserves the original interface:
\begin{itemize}[leftmargin=*]
  \item Observation: 23-dim vector (joint states, needle state, stress, progress, phase).
  \item Action: 7-dim bounded torque command.
  \item Reward: dense shaping + large completion bonus.
  \item Cost: indicator of force threshold or corridor violation.
\end{itemize}

\subsection{Scenario Families}
Three scenario families are implemented:
\begin{itemize}[leftmargin=*]
  \item \textbf{Nominal}: mild force noise and no corruption.
  \item \textbf{Perturbed}: stronger noise, dynamics shift, moderate corruption and delay.
  \item \textbf{Adversarial}: higher corruption, higher delay probability, harsher dynamics shift.
\end{itemize}

These scenarios are configured in \texttt{configs/scenarios/*.yaml}, allowing deterministic sweeps and curriculum usage.

\section{Algorithm Suite}
\subsection{Offline Methods}
\paragraph{CQL}
Conservative Q-Learning penalizes over-estimation on out-of-distribution actions by adding a conservative term to critic loss:
\[
\mathcal{L}_{\text{critic}} = \mathcal{L}_{\text{TD}} + \alpha_{\text{CQL}}\mathcal{L}_{\text{conservative}}
\]
The implementation keeps compatibility and adds deterministic evaluation support and explicit metadata in checkpoints.

\paragraph{IQL}
Implicit Q-Learning uses:
\begin{itemize}[leftmargin=*]
  \item expectile regression for value function fitting,
  \item advantage-weighted policy update for offline policy extraction.
\end{itemize}
This makes IQL a strong offline baseline without explicit behavior cloning as the sole learning objective.

\subsection{Online Constrained Methods}
\paragraph{SAC-Lagrangian}
SAC-Lagrangian maintains reward and cost critics and updates policy with dual penalty:
\[
\mathcal{L}_{\pi} = \mathbb{E}[\alpha \log \pi(a|s) - Q_r(s,a) + \lambda Q_c(s,a)]
\]
where \(\lambda\) is provided by the safety controller.

\paragraph{PPO-Lagrangian}
PPO-Lagrangian uses clipped surrogate optimization with separate reward/cost advantages:
\[
\hat{A}_{\lambda} = \hat{A}_r - \lambda \hat{A}_c
\]
The implementation supports trajectory building, GAE for both channels, and constrained policy updates.

\section{Hybrid Safety Stack}
\subsection{Runtime Decision Order}
The guard in \texttt{amasa/safety/guard.py} enforces:
\begin{enumerate}[leftmargin=*]
  \item policy proposes action,
  \item risk critic scores \((s,a,h)\),
  \item if risky, conservative transform is applied,
  \item decision-tree shield filters/blocks unsafe actions,
  \item environment executes final action,
  \item PID controller updates \(\lambda\) from cost violation.
\end{enumerate}

\subsection{PID Dual Control}
The Lagrange multiplier follows PID dynamics on violation error \(e_t\):
\[
\lambda_{t+1} = K_p e_t + K_i \sum_{\tau \le t} e_\tau + K_d (e_t - e_{t-1})
\]
with clamping to \([0,\lambda_{\max}]\).

\subsection{Safety Telemetry}
Per-step telemetry includes:
\texttt{lambda}, \texttt{risk\_score}, \texttt{shield\_blocked}, \texttt{cost},
\texttt{force}, \texttt{corridor\_violation}.
The pipeline exports \texttt{safety\_timeline.csv/jsonl/png} for post-hoc diagnosis.

\section{Failure Analysis and Practical Lessons}
\subsection{Observed Failure Modes}
\begin{enumerate}[leftmargin=*]
  \item \textbf{Conservative lock-in}: persistent high \(\lambda\) and high block rate reduce exploratory progress.
  \item \textbf{Scenario sensitivity}: on-policy PPO-Lagrangian underperformed in all smoke scenarios.
  \item \textbf{Unstable startup}: early online steps can show volatile reward critic updates before replay becomes informative.
  \item \textbf{Threshold mismatch}: fixed cost limits may be too strict for early perturbed/adversarial adaptation.
\end{enumerate}

\subsection{Engineering Fixes Applied}
During implementation and reruns:
\begin{itemize}[leftmargin=*]
  \item config overlay order was fixed so presets are not accidentally overridden;
  \item benchmark/sweep runners gained resume logic to skip already completed jobs;
  \item model save fallback was added for storage-sensitive systems;
  \item safety timeline export and plotting were added for online diagnostics.
\end{itemize}
